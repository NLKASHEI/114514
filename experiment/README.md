# experiment · 道渊 MVU 注入特化

版本 2.1.3。对现有角色状态做提示词投影，减少正文模型每轮收到的状态文本。

## 运行方式

在角色卡的酒馆助手局部脚本里新增投影脚本。

```js
import 'https://cdn.jsdelivr.net/gh/NLKASHEI/114514@experiment/experiment/道渊MVU注入特化.js';
```

需要完整的失败诊断时，把这张卡原有的 MVU 脚本内容替换成下面这一行。

```js
import 'https://cdn.jsdelivr.net/gh/NLKASHEI/MagVarUpdate@daoyuan-experiment/artifact/bundle.js';
```

保存后重新进入聊天。诊断构建与原 MVU 使用同一个局部脚本位。

- 投影从酒馆原生正文生成进入，只在聊天补全的请求就绪时替换一次。正文请求已有一个道渊变量列表的 `<status_current_variables>` 状态块，且替换后更短时才替换。没有状态块、试运行、识别到 MVU 额外模型、Pi 占位或显式复用正文状态块的脚本请求时直接跳过。
- 保留最近在场的人物及其必要描述。其他人物使用摘要，酒馆内原变量照旧。
- 默认只注入投影后的状态。结算结果进酒馆助手的「工具箱 → 日志查看器」。没有悬浮按钮、弹窗和逐轮浏览器控制台输出。
- `DaoYuanEXPR.set({ log: true })` 可以把净变化日志也加入正文提示词，默认关闭。`DaoYuanEXPR.preview()` 将最近一次投影全文写到日志查看器。
- `timeFix` 默认关闭。仅在明确开启时尝试回滚当前楼层的异常时间。

## 额外模型日志

常规 MVU 使用酒馆助手的生成事件，只记录收到的回复字数和变量结算摘要。变量结算行按楼层及当前候选回复对齐投影记录，显示状态块的压缩前后字数和节省量。单独的变量更新若找不到对应正文请求，只标明没有该楼层记录。只有配套诊断版能确认解析失败并以红色日志显示完整回复。

需要完整的解析失败诊断时，配合带 `daoyuan_mvu_extra_model_diagnostic` 事件的 MVU 构建。该事件在 MVU 格式适配之前捕获其收到的结果，并报告本次尝试是否通过解析校验。失败时日志显示完整字符串或工具调用对象，输出不截断。没有收到回复时明确记录没有输出。它记录的是交给 MVU 的模型结果，HTTP 头、密钥、供应商原始传输帧不在记录范围内。

配套构建由 GitHub Actions 每 6 小时检查官方 `beta`。诊断补丁可应用且测试、构建通过时，更新 `daoyuan-experiment`。同一张卡只应运行一份 MVU。解析通过和变量写入是两步，查看结算日志可确认后续变化。

## 本地验证

```bash
node experiment/test-local.js
node experiment/test-local.js "D:/path/to/chat.jsonl"
```

旧版实测中，6,831 字的状态投影到约 4,000 字。该数字来自旧版真实聊天存档的字符计数。本版按每次实际替换的状态块报告字数变化，模型 Token 节省需用真实请求用量核算。
